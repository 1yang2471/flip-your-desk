# Flip Your Desk · 设计说明

> 把桌面图标全部翻面，凭记忆把它们放回原位。

## 目标与边界

- 平台：Windows 10/11（首发），架构按平台适配层拆分，为 macOS/Linux 留接口。
- 技术：Tauri 2 + Rust + Vite/TypeScript + WebView2。
- 只做一件事：把真实桌面图标变成一局记忆翻牌游戏，结束时可选择写回新布局或恢复原布局。
- 不做：账号、云同步、排行榜、布局管理器、托盘常驻。

## 玩法

1. 启动小窗显示环境检测（图标数量、自动排列状态、桌面图标可见性、显示器）。
2. 点击开始后，每个显示器创建一张全屏无边框覆盖窗，壁纸保持原样。
3. 每个原图标位置显示一张统一“?”卡背；卡背按该位置背后壁纸的平均亮度自动切换深/浅两种色调。
4. 点击任意“?”格：从尚未抽出的图标池中随机抽一个图标，翻牌显示图标与名称。抽牌 +1 步。
5. 图标可拖动到任意格：
   - 目标格已有图标：两者互换；
   - 目标格还是“?”：图标占据该格，原格恢复成“?”；
   - 拖回原位或落在无效区域：弹回。
   每次拖拽释放 +1 步。
6. 全部图标抽完后出现“确定”。点击后停表并结算：
   - 正确率 = 最终落在自己原卡位的图标数 / 图标总数；
   - 只显示数字（正确率、正确数/总数、用时、步数），不显示具体哪个错了、原位在哪里；
   - 操作：再来一局（同一原布局，计时/步数清零）、保存新布局（回写桌面后退出）、回到原布局（写回原坐标后退出）。

## 计时与计步

- 计时从覆盖窗全部就绪、牌面出现时开始，到点“确定”时停止。
- 步数 = 抽牌次数 + 拖拽释放次数（拖回原位也算一次）。
- 不暂停（切窗、锁屏时间也计入）。

## 正确率

- 卡位与图标开局位置一一对应，槽位 ID 即图标 ID。
- 只有图标最终所在槽位等于自己的 ID 才计为正确。
- 不允许同槽多图标；每抽出一张，池子少一张，最终恰好填满所有槽位。

## 桌面读写（Windows）

- 通过 Explorer 桌面 `IFolderView2` 获取各图标位置、显示名、图标位图，并读取 `FWF_AUTOARRANGE`。
- 通过桌面 ListView 的 `LVM_SETITEMPOSITION32` 写回位置（32 位坐标，支持负坐标/多屏）。
- 写回前备份原布局（名称、坐标、图标尺寸、显示器配置、时间戳）到应用数据目录。
- 写回后重新读取并校验；失败则按备份回滚，并向用户显示错误。
- “自动排列图标”开启时禁止开始，并在启动窗给出关闭指引。
- “对齐到网格”保持开启无妨；读写坐标均使用 Explorer 当前坐标。

## 覆盖窗与多显示器

- 每个显示器一个 Tauri 无边框窗口，按物理像素铺满该显示器，置顶、无任务栏按钮、不可关闭。
- 覆盖窗按 `monitor.origin + physical position / scale_factor` 换算 CSS 坐标，保证不同 DPI 下牌位对齐。
- 后端是唯一游戏状态源；每个覆盖窗只渲染本屏的槽位，通过 Tauri 事件同步。
- 跨屏拖拽依赖指针捕获 + 全局物理坐标命中测试；若实机验证不可行，降级为同屏拖拽并在 README 说明。
- 壁纸通过 `IDesktopWallpaper` 读取每台显示器的文件与填充方式；无法读取时退回纯色背景。
- 卡背深浅：优先在前端用 canvas 采样当前渲染区域的壁纸亮度；无法采样时使用后端给出的整屏亮度。

## 稳定性

- 游戏过程中从不改动真实桌面；只有结算“保存新布局”才写回。
- 应用崩溃/被结束时覆盖窗随进程消失，桌面保持原样。
- 退出（Esc）需二次确认，确认后直接退出，不保存本局。
- 结算阶段锁定操作，避免重复提交。
- 图标数 < 2、桌面图标被隐藏、Explorer 视图找不到、自动排列开启：均在启动窗拦截并给出中文指引。

## 视觉与动效

- 壁纸不暗化、不模糊，保留“这是我的桌面”的临场感。
- 卡背：自适应深浅磨砂卡（深色底/浅色底两种色调，同形状、同圆角、同问号、同高光）。
- HUD：极简浮层，显示进度、计时、步数、静音、退出；自动避开牌位选择摆放位置。
- 翻牌 280ms 3D 翻转；悬停轻抬；拖拽放大微倾 + 深阴影；换位弹性动画；结算卡滑入。
- 音效由 Web Audio 合成（翻牌沙声、落位嗒声、完成叮声），启动窗可静音。

## 国际化

- 界面语言：简体中文（`zh-CN`）与 English（`en-US`），文案集中在 `src/locales/*.ts`，新增语种=新增一个字典文件。
- 默认跟随系统语言，可在启动窗一键切换并记入 `localStorage`；游戏内沿用开局时的语言。
- 后端只返回稳定的问题码（如 `auto_arrange_on`），文案由前端按语言渲染；错误详情仅进控制台。
- 数字使用 `tabular-nums`，计时统一 `mm:ss`（超过一小时显示 `h:mm:ss`）。

## 视觉方向（所有视觉决策以此为准）

1. **受众与场景**：Windows 桌面用户，熟悉自己的图标摆放；用鼠标、1–3 块屏，玩 2–5 分钟。
2. **目的**：把真实桌面变成一局记忆挑战；结束时让玩家知道“我记得有多准”。
3. **视觉性格**：触感、精确、轻巧的玩心；密度偏疏。刻意**不**做霓虹、彩色渐变、满屏玻璃拟态、游戏化徽章。
4. **布局**：全屏桌面场景 + 漂浮紧凑控件；启动窗是单卡；结算是聚焦卡；HUD 自动避开牌位。
5. **字体**：一套系统字体（Segoe UI Variable / 微软雅黑），12/13/15/20/40 五级，数字 `tabular-nums`。
6. **颜色**：一条石墨中性色阶；颜色交给壁纸；只用一个暖金 accent（“?”与主按钮）；成功绿仅用于就绪状态。
7. **交互与无障碍**：鼠标拖拽 + 完整键盘路径；焦点环、44px 命中区、reduced-motion、4.5:1 对比度；每个交互面都有 hover/focus/active/disabled/loading/empty/error。

签名细节：**会随壁纸明暗变色的“?”卡背**，只出现在“原本是图标”的位置上。

## 开发与交付

- 开发调试提供 mock 模式（假图标 + 渐变壁纸），不触碰真实桌面。
- Rust 单测覆盖：几何换算、正确率、备份序列化、命中测试。
- GitHub Actions：push/PR 跑 `cargo test` + `npm run build`；tag 触发 Windows 安装包/便携 exe 构建并发布 Release。
- 交付：NSIS/MSI 安装包、便携 exe、源码、双语 README、MIT License。
